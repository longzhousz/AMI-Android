## 缺封面排查

**当前没有联网搜索/补全专辑图功能。** 先确认用户歌曲中是否实际存在可读取的图片，再判断是否需要未来增加补图。不能将缺图统一归因于图片服务器或网络。

当前读取链路在 `app/src/main/java/com/longzhousz/ami/data/LibraryScanner.kt`：

1. `MediaMetadataRetriever.embeddedPicture` 读取音频内嵌图片。
2. 前者为 null 时使用 NCM 头部的非空图片。
3. 仍为 null 时使用音频所在目录的 `cover`、`folder`、`front` 文件，支持 `jpg`、`jpeg`、`png`、`webp`，名称大小写统一处理。
4. `cacheCover()` 检查可解码性，采样并以 JPEG 写入应用私有封面目录，数据库记录路径。
5. `ui/Components.kt` 的 `Cover` 使用 Coil 读取本地图片；无路径显示占位。`PlayerArtworkScene.kt` 处理封面转场，`PlayerBackdrop.kt` 处理取色。

排查时特别核实：有非 null 但空白/损坏的内嵌图片时，后续 NCM/同目录分支是否被跳过；图片只在专辑父目录或其他名称下时是否在当前搜索范围；NCM 标签、CUE 与文件夹授权是否影响实际来源；增量扫描复用的封面路径是否仍存在。以上是由代码得出的检查点，尚未用用户缺图样本证实。

建议流程：

1. 先保留手机现有安装与曲库，记录 3–5 首缺图、1 首正常歌曲的格式、艺人、专辑、来源文件夹、是否内嵌图片及旁边的图片文件名。无需上传整套私人曲库。
2. 通过 USB 在现有应用中分别观察歌曲列表、专辑页、播放页和系统媒体面板，确认缺图出现在哪些位置；保存相关截图和只读诊断。
3. 对已获授权的少量源文件检查标签/图片；若不可调试 Preview 隐藏了内部原因，再在独立 Debug 安装中导入相同样本，比较扫描结果、图片缓存和 UI 请求。
4. 确认是来源无图、搜索范围、读取/解码、扫描缓存还是显示问题后，再决定修复现有读取链路，或另行设计后台联网补图。保留简洁前台，不增加诊断面板。
