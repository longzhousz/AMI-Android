# 播放连续性与页面记忆：0.1.17

应用 0.1.17 / versionCode 18；本地曲库 schema 4、在线音频缓存 schema 1 保持不变。继续使用 `musicPreview` / `com.longzhousz.ami.musicpreview`，覆盖云端 0.1.16 时保留登录、设置、曲库和译文。本轮不连接 vivo X300。

## 默认封面与页面记忆

新选歌曲默认展示完整封面，包含有歌词的歌曲。切到歌词后收起，再打开同一首歌会回到歌词；封面页也按相同规则保留。重新选择歌曲（包括列表中再次点当前歌曲）或切换曲目会重新默认封面。读取歌词、更新译文或收藏状态不重置页面。

页面选择保存在播放页之外，因此下拉、按钮和系统返回销毁弹层后，仍保留本首歌的选择。只保留当前歌曲的歌词页面状态，不积累所有听过的歌曲页面。封面放大／缩小仍使用同一张图片、可中断的弹簧与原有手势；0.1.16 的单窗口下拉交接、系统栏配置和缩略图圆角继续保留。

## 换歌衔接

封面改用单个当前 Coil 请求，保留一张最近成功解码的图片作为加载占位。新图成功解码后再渐变替换，避免网络尚未返回就先把旧图淡成空白；切换地址后使用独立的 Painter，新请求不等待旧请求完成取消，过期请求不能更新当前占位。即使旧图片的内存缓存键被淘汰，仍能衔接最后一张已解码画面。真正加载失败时显示当前专辑的占位图。内存命中直接显示，不额外等待一次加载动画。

标题和歌词使用相同的短转场节奏，背景取色也在约 360 ms 内变化。背景仍在 IO 线程采样小图、使用有界颜色缓存，没有常驻背景动画。封面继续按请求下载原图、跨页面共享原始文件、按最近使用保留一周，不抓取整库或提前下载邻曲封面。

直接使用 Media3 1.11.1 的 `ExoPlayer.PreloadConfiguration`。播放中为相邻项目启用目标约两秒的额外内存预加载；Media3 的 LoadControl 先满足当前播放的加载需求。暂停、缓冲、单曲循环和单项队列关闭额外预加载池。普通播放的缓冲策略保持 Media3 行为，分块与格式可能让实际读取量超过两秒；不将这些数据另存为整首离线文件，也不承诺所有网络和编码组合下绝对无缝。

下一首歌词在前台当前歌曲稳定播放约 700 ms 后少量准备，包括在线歌曲。仍只准备一个相邻曲目，沿用 2 MiB 正文／解析缓存；暂停、切歌或退后台取消这次准备。没有翻译生成、封面预取或周期轮询；失败不干扰当前歌曲。

## 歌词定位与跟随

歌词和进度条共用一次明确跳转的目标预览。在播放器确认前，旧进度不能把歌词拉回旧段落；连续跳转只保留最后一次目标。点击歌词、点击或拖动进度条都会立即定位到目标句，并恢复跟随；手动翻阅仍暂停跟随，继续保留「回到当前句」。

相邻句使用原有弹簧滚动。较远跳转直接定位，中间以短渐隐衔接，不快速掠过所有段落。保留长句／双语的自然行高、换行、当前句高亮与轻微缩放，不引入逐行模糊。歌词未显示时没有歌词列表的逐帧计算，退后台仍停止可见区域的帧时钟。

## 缓存让路

封面显示请求不再顺便扫描整个缓存目录。最近使用时间仍按请求／内存命中续期；目录回收改在界面退后台或播放加载完成后的 IO 工作中处理，离线也可以清理。新界面或播放加载返回时，遍历会尽早让出。

常听记录只更新少量历史，不在有效收听的瞬间扫描文件。完整音频补齐使用既有单次 WorkManager 小批次，要求联网、非低电量且存储状态正常；前台主界面未显示、播放器完成加载且没有导入时才启动。进行中的副本允许正常播放补缓冲，避免大文件被每次补缓冲打断后反复下载；返回前台、真正缓冲不足或开始导入时，下载按块检查并放弃本次临时文件，下次有空闲窗口再尝试。这种让路不记为网络失败，不产生一天的失败退避。

音频仍采用近七天三次有效收听、七天未听回收、最多两首一批、默认 512 MiB／用户可选上限、单首最多 256 MiB、至少 1 GiB 剩余空间的策略。移动网络仍允许；正在播放文件、源音乐和导入的 NCM 转换结果保留。手动调整缓存上限属于明确操作，仍在 IO 线程执行对应回收。

## 验证范围

新增回归覆盖默认封面、两种页面收起重开、重新点当前歌与换歌重置、慢图片／缓存键淘汰／过期图片返回、跳转时旧进度确认、在线邻曲歌词复用、缓存让路不误记失败以及封面请求不触发目录扫描。原生高解析度 FLAC 测试继续核对 96 kHz / 24-bit 输入、拖动和自然推进到下一首。

沿用 10,000 首曲库与大歌词回归，以及后台播放、系统媒体键、进程回收恢复、下拉反向手势等检查。连续六次切歌／十二次跳转／六次播放页开关的聚焦流程会保存 Perfetto、gfxinfo 和前后两份 meminfo；它们来自软件渲染 Debug 模拟器，作为问题排查证据，不能推断 X300 的帧率、长期内存、续航或真实网易云网络等待。

本轮使用 Debug / Pixel 2 配置的 x86_64 软件渲染模拟器，每套系统各采样一次。聚焦流程为六次切歌、十二次跳转、六次播放页开关和三次封面往返，45 秒 Perfetto 覆盖完整流程，同时保存 gfxinfo 与前后 meminfo。
