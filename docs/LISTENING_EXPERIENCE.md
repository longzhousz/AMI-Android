# 封面、逐字歌词与发现音乐：0.2.4

应用 0.2.4 / versionCode 26，继续使用 `com.longzhousz.ami.musicpreview`，本地曲库 schema 5，在线音频缓存 schema 1 不变。手机独立运行；保留原有封面、歌词、迷你播放器和数据。

## 曲库封面回看

原图已经落盘，不等于所有高清位图都能常驻内存。原有内存预算会淘汰较早的解码结果，回滚又需要 IO 和解码；Cover 还会为磁盘读取重做渐显。16 个下载锁还可能让已经缓存的图片排在无关的新图下载后面。

当前只在用户请求过图片后保留一个最长边不超过 96 像素的小预览，优先使用 RGB565，并以堆空间 5%／16 MiB 中较小者限制总容量。它独立于高清位图缓存，高清缓存淘汰后仍能在重新进入条目的第一帧同步显示。高清结果就绪后直接替换；新选歌曲之间的封面渐变保留。内存压力或退后台仍可释放这些可重建数据。

预览来自已请求的原图，不增加图片下载或磁盘缩略图副本，不提前抓取整库。原图保留最近使用一周的策略不变。已完成的磁盘文件优先读取，不再等待无关下载锁，读取时按小时续期，减少快速回滚的文件时间戳写入。写入标记和打开的文件句柄避免读取未完成文件及回收竞争。

网格仅为刷新重排保留位置弹簧，条目进出视口不重复淡入。专辑原图仍保持方形；迷你播放器缩略图沿用圆角。

## 真实逐字歌词

优先读取网易云歌词 v1 的 YRC，端点异常时兼容原 LRC 请求；登录失效明确保留鉴权错误。服务端没有逐字数据、文字不一致或时间无效时沿用普通歌词，不推算或伪造字时长。

YRC 按同一段文字及邻近时间匹配原 LRC 行，只附加逐字／词区间。原文、行顺序和行时间保留，因此原有 AMI 翻译的索引与缓存键不因添加逐字数据变化。重复副歌按各自时间匹配，字符区间使用 TextLayout 的 UTF-16 偏移，保留长句换行、空格和双向排版。

只有当前跟随中的原文使用一层透明度遮罩，按真实词区间逐渐亮起。播放时钟在绘制阶段读取，不逐帧重建文本布局；暂停、隐藏歌词或退后台沿用原有时钟停止规则。译文、手动翻阅及普通行保留原来的显示方式。解析在加载线程完成，原文、YRC 和解析结果都计入既有 2 MiB 歌词缓存预算。

## 一个发现入口

曲库顶部新增一个「发现音乐」图标，菜单仅有「私人 FM」「每日推荐」。用户主动选择后再请求，取得可用歌曲后直接打开原有封面播放页。没有新导航标签、推荐信息流或后台定期刷新。

每日推荐沿服务端顺序进入普通队列。私人 FM 从顺序、不循环整队开始，在服务端有后续歌曲时继续补入队尾，不重置正在播放的歌曲和进度。播放服务在接近最后两首时按事件取一小批，暂停后不轮询；失败、重复结果或无权限歌曲不造成无限重试。队列至多 1,000 首，保存元数据不超过 2 MB。

队列文件原子保存曲目和本轮 FM 标识，兼容读取旧的数组格式。FM 标识与账号绑定；切换队列、退出账号或取消请求后，旧结果不能追加到新队列。只读取推荐，不写入红心、歌单或收听记录到网易云账号。实际播放仍经过既有音源权限和试听拒绝检查。

## 专辑连续转场

曲库封面与专辑／歌单详情通过 Compose 原生共享元素匹配。点击时同一张封面从卡片位置展开到较大的详情封面，返回时缩回原卡片；网格滚动状态在转场外保存，手动刷新仍按原规则重排并回到顶部。

只有可见卡片挂接共享元素，避免整库跟踪坐标。原图边角、曲序、播放队列、单窗口播放页下拉和系统栏配置保留。每次打开详情从顶部开始，返回曲库保留网格位置；共享封面按专辑保持稳定标识，访问 ID 仅用于重建详情列表，快速返回时旧详情使用独立列表状态，避免动画期间两个页面共用同一个滚动布局。
