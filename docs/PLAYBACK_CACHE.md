# 播放缓存与界面整理：0.1.15

应用 0.1.15 / versionCode 16，延续 [0.1.14 在线音源](ONLINE_LIBRARY.md)；原本地曲库 schema 保持 4，缓存使用独立的私有 SQLite 索引。用户目前只有手机，本轮不连接 X300。

## 使用变化

- 首页三个图标改为底部悬浮导航，迷你播放器同样悬浮。单击立即切换，双击曲库或我喜欢主动刷新；内容可以延伸至控件下方，末尾留出滚动空间。
- 曲库搜索改为右上角按钮，点击展开。下拉／双击只重排卡片，至少两张时首卡必定更换，并回到新顺序顶部；专辑内部与当前队列曲序不变。
- 我喜欢保留已载入列表和滚动位置，切换标签不重新请求。主动下拉／双击刷新时才重新取该列表。每次分页仍为 30 首，不因布局变化预先拉完整歌单。
- 专辑封面不加圆角或阴影，以完整原图显示；保留现有可打断的移动／缩放转场。
- 歌词页底部三个操作只显示图标，保留无障碍名称。右上角「歌词选项」显示当前音源档位，有损音源同时显示已知码率；尚未取得音源时显示「待确认」。该值来自音源响应，不代表耳机实际输出或空间渲染结果。
- 默认只展示原文与 AMI 已生成的翻译，不自动使用网易云自带译文。自带译文可以留存在后台，但不触发付费翻译，也不覆盖用户已有的 AMI 翻译。

## 自动播放缓存

只用手机运行，不增加下载入口、任务列表、进度或缓存标志，歌曲 ID、歌词、播放页和队列保持不变。

1. 一次播放累计实际出声 30 秒算有效收听；短曲以半首为准，至少 3 秒。同次连续播放只算一次，重新播放或循环可形成下一次。暂停、缓冲、拖动进度及恢复的历史位置不计入收听时长。复用现有播放检查点，没有新增计时轮询。
2. 近 7 天至少 3 次有效收听，才进入缓存候选。按用户选择，Wi-Fi 和移动网络均可通过系统 WorkManager 补齐完整音源，每批至多 2 首；没有周期唤醒或额外前台服务，系统可能延后执行。
3. 使用当前账号有权取得的原歌曲音源，不寻找替代歌曲。完整大小、可用时的 MD5、音频时长校验通过后，才原子发布本地文件。未完成或校验失败的文件不能用于播放，不持久化临时 URL 或 Cookie。
4. 以后优先读本地完整文件；文件缺失或缓存存储不可用时继续在线解析。损坏文件在播放失败后移除并尝试同歌曲、同进度重新在线准备一次。缓存不改变界面，也不等同于完整离线曲库：列表和歌词仍有各自的加载条件。
5. 最多 512 MiB，单首最多 256 MiB，并为手机剩余空间保留至少 1 GiB。需要空间时先回收较久未听的副本，不回收正在播放的文件；不足以安全保存时跳过缓存。失败候选延后至少一天再尝试，避免重复耗流量。
6. 7 天没有有效收听的副本，在下次启动播放服务或缓存工作时回收；不为清理专门唤醒手机。收听索引只保留最近至多 2,000 条未缓存记录。退出／切换账号回收该缓存，账号之间不复用音频。系统也可以清理应用缓存。

只允许删除在线缓存专用目录里的 AMI 文件。`AudioCache` 中原有 NCM 转换结果、用户导入源文件、收藏、文件夹授权、歌词和翻译不受这项自动回收影响。

## 性能与验证边界

两个主标签各保留一份已载入歌曲列表，不为每个访问过的专辑建立无限缓存；最多各 20,000 首。歌曲合并／去重与新歌词解析移到后台线程，歌词页不再预先解析不用的内嵌译文。缓存文件下载和 SQL 索引也在 IO 线程，暂停时没有新的周期任务。

新增测试使用生成的 96 kHz / 24 bit FLAC、合成账号与 HTTP 夹具，覆盖有效收听、手动刷新、列表复用、首卡变动、实际音源显示、完整／损坏文件、校验拒绝、容量与过期回收、账号隔离。不得在用户日常安装上运行会写夹具的完整仪器套件。

本页将在交付时补充本地检查、模拟器结果与 APK 摘要。模拟器证据不代表 X300 的实际流畅度、续航、真实 VIP 音源、耳机音质或原子岛效果已验证。
