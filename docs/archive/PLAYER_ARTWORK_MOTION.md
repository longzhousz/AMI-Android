# 0.1.9 播放页与后台优化

> 历史归档：以下版本号、操作入口和验证结论仅对应当时的代码。当前版本请从 [文档索引](../README.md) 开始；归档不代表这些步骤仍是推荐用法。

## 交互与布局

歌词页的 48 dp 小封面与封面页的大封面由同一个图像节点绘制。点击小封面时先离开歌曲信息行，再向上放大；大封面下滑时先缩小再落回小封面位置。两端坐标从实际布局测得，旋转、系统栏及字体缩放后重新测量。固定父容器接收拖动，缩放图像不会改变手指移动的坐标系。弹簧可被拖动或反向切换中断。

过渡期间保留歌词渐隐、轻微位移与封面阴影。每帧更新集中在图层，时间轴仍独立刷新；歌词段落定位由线性扫描改为二分查找。封面模式完全展开后不保留隐藏歌词的逐帧计算；返回时恢复歌词浏览状态。

底部为歌曲名、艺人与喜欢操作，细进度条与时间，居中的主要播放控制，最后是封面/歌词、翻译/译文与队列。窄屏和横屏采用紧凑间距。定时停止入口、弹窗、ViewModel 方法、偏好监听与后台计时任务均删除；服务启动清除旧版期限。

## 大曲库收藏

使用 Kotlin 官方 `kotlinx-collections-immutable` 0.4.0 的持久化集合。单次收藏只修改歌曲、所属专辑、ID 映射和收藏集合，共享其余记录及搜索/分组/排序索引，不重新读取整库元数据。旧快照保持不变，退出中的界面不会被原地修改。

数据库按 ID 读取当前收藏状态后切换，避免旧界面中同一份 Song 对象连续点击只能设置一次的问题。完整扫描与收藏更新通过同一仓库锁发布，防止覆盖彼此结果。

## 后台与验证

内存压力回调清理可重建的歌词、图片与封面取色缓存，保留磁盘正文及音频。Android 新版本的回调策略受系统控制，不添加应用内存轮询。UI 隐藏时原有歌词预取仍停止。

自动回归加入封面中间尺寸、单图像节点、下滑返回、反向点击与拖动反转检查，保存中间和两端截图；保留原有歌词、大字号、进度、队列和返回断言。收藏测试覆盖旧对象连续点击与未受影响专辑复用；内存压力测试验证清缓存后歌词可再次读取。

连续交互采集增加三个封面往返，Perfetto 窗口延长为 45 秒，并记录是否覆盖完整操作。主机后台恢复后增加 8 秒暂停 CPU ticks 及前后内存快照。这些仍是软件渲染模拟器中的功能和诊断证据，不能换算为 X300 的帧率或耗电收益。实际 30 分钟熄屏、蓝牙、来电与原子岛仍需对应真机验收。

原子岛的实验接入和边界见 [OriginOS 兼容性记录](../ORIGINOS_COMPATIBILITY.md)。
