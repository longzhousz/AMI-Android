# Android 后续优化

依据当前 Kotlin / Compose / Media3 实现整理。优先提高日常播放和歌词功能的完整度。

## 本轮：模型与预设自动更新

- 默认跟随 DeepSeek 官方最新 Flash 别名；支持自动 Pro、官方模型列表与手动 ID。
- 有密钥时在前台每日刷新，支持立即更新、关闭自动更新、本地缓存、失败退避和无密钥离线使用。
- 新预设不会覆盖手动选择，不会跨 Flash / Pro 系列切换，不会自动触发收费翻译。
- 保留旧译文；「重新翻译」确实跳过旧缓存。同一翻译任务固定模型和风格。
- 通过官方 `GET /models` 获取显示名与文字能力，不按列表顺序猜测模型新旧，也不抓取网页生成模型 ID。

## P1：让翻译成为可管理的任务

目前 `TranslationClient` 每批处理 50 行，整首成功才缓存；`AmiViewModel` 对外只暴露翻译中的布尔值。长歌词失败后需要整首重来，界面缺少进度、取消和错误定位。

下一步增加按歌曲管理的任务：显示完成行数、允许取消、对临时错误有限重试、保存已验证的分批结果后续传。保留完整的逐行校验，只合并属于同一歌词、模型与风格版本的分批结果。显示译文的模型名称、生成时间和风格，支持保留或切换旧版本、导出双语 LRC。模型升级只影响新请求，不静默重译或额外发起收费请求。

验收：切歌时译文不串歌；取消后不回写；中途断网后只恢复未完成批次；错误批次不能污染已保存译文；重新翻译与普通读取缓存的行为明确。

## P1：大曲库增量扫描与搜索

`LibraryScanner.scan` 仍遍历整个授权树并逐首读取媒体元数据；每 12 个条目触发一次整库重载。`LibraryDatabase.songs` 每次读取整库，搜索和专辑搜索在内存中遍历并拼接字符串。曲库扩大后，导入、搜索响应和内存占用会先受到影响。

下一步记录文档 ID、修改时间和大小，未变文件跳过元数据解析与封面读取；分批事务写入、减少整库重载；建立搜索索引并逐步分页。对撤回授权、文件迁移和删除提供明确的修复入口，扫描异常时保留收藏、曲序及手动歌词。

验收：用千首及万首曲库比较首次扫描、无变化重扫、搜索响应和内存占用；重扫不重复导入，不丢用户设置。

## P1：后台播放、耗电与真机流畅度

`PlaybackService` 已有 MediaSession、音频焦点、耳机拔出暂停与队列恢复。当前每两秒持久化时仍遍历并序列化整个队列，即使歌曲队列未变。动效回归已覆盖手势逻辑，厂商系统、长时间熄屏和真机帧时间还需单独验证。

下一步将队列持久化改为结构变化触发，定期只保存必要的播放位置，暂停时停止周期写入。在目标 vivo 手机验证长时间熄屏、蓝牙断连重连、来电打断、通知操作与进程重建，并用帧时间、掉帧和内存数据确认播放页及大曲库滚动效果。先验证无缝跨曲，再评估交叉淡入与睡眠定时渐弱。

验收：暂停与后台场景减少无效写入；锁屏和蓝牙操作保持一致；恢复队列及位置准确；用同一真机、同一音乐和同一操作比较优化前后的数据。

## P2：曲库整理与可迁移性

增加播放列表、最近播放、元数据缺失提示及批量整理入口。提供只包含曲库记录、收藏、手动曲序、歌词与译文的可预览备份/恢复；密钥与音频另行处理。恢复先展示路径与授权修复结果，再应用变更，避免文件移动后出现大量失效歌曲。

## 公开协议依据

- [DeepSeek 模型列表 API](https://api-docs.deepseek.com/api/list-models/)：模型 ID、显示名称、输入/输出类型和能力。
- [DeepSeek 更新日志](https://api-docs.deepseek.com/updates/)：当前 Flash 移动别名与旧调用名的迁移。
- [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)：模型调用和 thinking 参数。

预设更新不需要 AMI 发布新版本；如果供应商改变 API 协议、鉴权方式或废弃整个模型系列，仍需要适配代码。
