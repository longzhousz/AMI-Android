# 我的聆听

从 0.1.19 开始记录，0.2.4 沿用本页统计口径与 schema 5。

设置页靠上直接展示独立入口，不需要展开分组。采用纵向图鉴，包含周、月、年三种自然日历周期，周从星期一开始。首次默认本月，之后记住类型，重新打开进入当前周期；左右翻看往期，点击日期选择历史，下拉手动刷新。

## 内容与口径

首屏显示总时长、歌曲数、听歌天数及本期最长连续听歌天数。下面依次为时长趋势、日历热力图、累计时长前十首、前五位歌手与其他的环形图、前六张专辑、星期与小时分布，以及初遇／重逢比例。年报的趋势按月汇总，日历展示十二个月。所有提示文案直接由数字生成，不调用模型。

时长按 Media3 实际播放状态及 `elapsedRealtime` 的经过时间累计，独立于媒体进度；暂停、缓冲和跳转不增加时间，倍速播放十分钟仍记十分钟。换歌和结束前的片段归前一首，循环听同一首继续累加。歌曲数为本期实际发生播放的唯一曲目数，不设额外收听门槛。

有可靠网易云 ID 时，在线、缓存和对应 NCM 归到同一首；其余使用原歌曲身份，不按同名猜测版本。新增可选的主艺人和专辑 ID，随现有歌曲元数据与队列传递，旧队列缺少字段仍可恢复。合作曲优先归首位署名艺人，缺少结构化信息时保留原署名，不拆猜斜杠、逗号或艺名。已有真实 ID 不被旧队列里的姓名降级覆盖。

“本期初遇”是首次在 AMI 记录的日期属于本期的歌曲，其本期总时长计入初遇；其余归重逢。它不表示发行年代，也不能推断用户以前在其他播放器是否听过。占比按同一总时长计算，图例使用最大余数舍入，合计为 100%。

当前周期按已进入的日历天数与上期比较，上一周期不足相同天数时截至其末日；本期今日仍在累计。只有两个比较区间都在记录开始之后、数据无已知缺失时才给出比较。上期为零时显示未听歌，不计算无限百分比。开始记录前与未来日期留空，不用零值冒充已知历史。

## 数据与资源

沿用应用 SQLite，schema 从 4 非破坏升级至 5。新增三类数据表：

- `listening_tracks`：一首歌一份必要元信息、来源标识、主艺人／专辑标识和首次记录日期；封面仅存已有地址或路径。
- `listening_song_day`：日期 × 歌曲的累计毫秒。
- `listening_hour`：日期 × 小时的累计毫秒，查询时汇为星期 × 小时。

另有单行 `listening_status` 标记已知记录缺失。统计表不依赖曲库歌曲的删除级联。清缓存、删除源文件、换账号不清统计；“清除聆听记录”只清这几张表，需用户确认，不修改歌曲、账号、队列或译文。

播放线程只更新少量内存计数，不读写数据库、不遍历队列。待写聚合条目及每次提交批次各最多 256 个，由单个后台写入器合并提交；数据库失败留到下一个真实检查点重试，不创建轮询或无限队列。超过缓冲上限时标记可能不完整，保住播放与内存边界。

复用现有十秒检查点，在暂停、换歌、结束时尽快提交。正常存储可用时，进程强杀仍可能遗漏最后约十秒；不以恢复后的播放位置补造这段时间。日期、小时使用片段当时的设备时区，跨午夜及夏令时边界拆分；实际时长始终由单调时钟决定，手机时钟调整不增加时长，已保存分桶不追溯改写。

打开、切周期、下拉刷新才查询，页面停留时不自动刷新。报告最多 366 天、168 个小时格、10 首歌、6 个歌手分组及6张专辑；SQLite 聚合、排序和限量在 IO 线程完成，不把全部历史搬到内存。退出释放报告，保存状态只保留类型、日期和滚动位置。图表原生 Compose 绘制，首次进入视口动画约 360 毫秒，离屏或后台取消，回滚不重复播放。

不新增依赖、权限、定时任务或网络统计接口。封面复用既有按需缓存，不保存报表图片或额外音频。用每天 50 首不同歌曲的简化合成数据粗算，统计约新增 1～5 MiB／年，随新曲数量变化；这是规模估算，实际 Android 证据以本轮测试为准。用户选择长期保留汇总，不自动淘汰往年周报或排行。
