# Android 验证记录

更新日期：2026-10-23。目标 Android 17 / API 37，最低 Android 8.0 / API 26。

## 0.1.4 界面精简与独立工程

安卓版已提取为独立 Gradle 根工程，源自 `longzhousz/AMI` 的 `0cb32f4`；初始提取提交为 `0265191`。原包名、预览签名与 schema 2 延续，版本代码递增至 5。

曲库默认直接显示歌曲；曲库和收藏页删除品牌大标题、口号、右上角导入加号及宣传卡片。导入统一在设置中；空曲库提供前往设置的入口。专辑详情改为紧凑封面与歌曲列表。播放页去掉重复标题、格式标签及菜单中的只读技术信息，保留沉浸式歌词、译文显隐、重新翻译、定时停止与播放控制。

搜索使用系统搜索键收起键盘，搜索或排序变化回到结果首项。设备界面检查新增搜索、两种排序、收藏过滤、专辑进入与返回、点歌播放，并保存曲库、收藏和专辑截图。

本地 20 项核心测试、Debug 和设备测试包编译已通过。优化安装包及 Android 11 / 17 设备验证仍在进行；真机体验尚未验证。

## 0.1.3 沉浸式歌词

产品代码 `4b92f79` 将固定 305 dp 的歌词小窗改为自适应完整播放页。封面在后台采样取色；歌词以自然段落高度排版，使用 28–36 sp 原文、17 sp 译文、当前句暖白高亮、前后句淡出、轻微景深与上下边缘渐隐。放大字体时取消景深；API 30 使用清晰文字与透明度层次。

跟随使用 MediaController 的本地准确时钟，仅在播放页处于前台时读取，不提高曲库全局刷新频率。按当前段落实际高度平滑定位；手动拖动暂停跟随，提供「回到当前句」，点句子可跳转。无时间轴歌词自由阅读，无伪造逐字进度。已有译文可直接显示/隐藏，重新翻译改为明确的菜单操作。

完整播放页使用独立深色内容与系统栏，保留队列、收藏、随机/循环、定时停止及单曲歌词导入。横屏分栏；顶部下拉收起与歌词浏览手势分开。细进度条保留原有滑动和无障碍跳转语义。

[构建与 Lint 任务](https://github.com/longzhousz/AMI/actions/runs/39804378289/job/119914246603) 已通过：20 项 JVM 测试、Lint、优化 Preview 与 Release 构建。本地最终交付 APK 同样通过 20 项测试、Lint（0 Error）、不可调试设置、原预览签名与 16 KB zipalign 检查。

[实际交付 APK 覆盖升级检查](https://github.com/longzhousz/AMI/actions/runs/39805750122) 在 API 30 和 API 37 均通过。从发行页下载 0.1.2 初始化数据库后，覆盖安装 0.1.3，检查两次冷启动、设置页和网易云歌词入口；两个设备报告中的 SHA-256 均与交付文件一致：`0a4cee67cddccc1b1b79ce3914ac016ed4243bcee45b0ce030e96fe553b49e27`。未记录到 AMI 进程崩溃。APK 为 2,747,995 字节，版本代码 4，包名 `com.longzhousz.ami.preview`，可直接覆盖上一预览版。

歌词设备回归新增三项测试，覆盖双语显示、自然段落定位、点句/进度条跳转、手动浏览暂停跟随、返回当前句、隐藏译文、封面切换、320 dp 宽度下的 1.5 倍字体，以及无时间轴歌词。完整窗口检查还覆盖打开队列后返回、收起按钮和顶部下拉手势。[最终设备回归](https://github.com/longzhousz/AMI/actions/runs/39882305078) 已通过：Android 11 / API 30 与 Android 17 / API 37 各 11 项，均为 0 失败、0 错误、0 跳过。已检查两套设备的歌词截图及 Android 17 完整播放窗口，双语排版、控制区和细进度条显示正常。

早先两次 API 37 设备回归未能启动模拟器，日志为 `Not enough space to create userdata partition`：镜像至少需要约 7.4 GB，设置 2 GB 数据分区也无法缩小镜像自带的 userdata。CI 现清理临时测试机上不参与 Android 构建的预装 .NET / Swift 工具链，给 API 37 显式配置 8 GB 数据分区；先编译测试包再启动模拟器，避免编译与虚拟设备争用资源。新增仅运行设备验证的手动入口；这些改动不改变产品代码或实际交付 APK。另一次镜像下载遇到 ZIP 读取错误，重试该设备任务后全部通过；上述失败均发生在运行应用之前。设备配置对应提交 `252163c`，与产品提交 `4b92f79` 的 Android 工程完全一致。

仍需在 vivo X300 上确认实际字体、封面及曲库体验；以上为硬件加速模拟器验证。横屏、折叠屏和最低 API 26 的专门验收仍保留在后续真机范围。

## 0.1.2 网易云数字歌词导入

产品提交 `0045e0b` 新增 NCM `musicId` 与数字歌词文件的精确关联；支持无扩展名文件、普通 LRC 和网易云 JSON。测试包含用户提供的结构：`lrc` 字段内先是 -1000 / -500 ms 的 `{t,c,tx}` 制作信息，再接毫秒 LRC 时间轴。制作信息保留为 0 ms 歌词，链接字段忽略；已有译文按时间戳对齐。

采用用户选择的复制/导出目录方案：先把 `Android/data/com.netease.cloudmusic/files/LrcDownload` 复制到普通目录，再通过系统文件夹选择器授权读取。无 Shizuku 或全盘访问权限。歌词内容保存在本机 SQLite；歌曲先导入或歌词先导入都可匹配。同名 LRC 优先于数字缓存；单曲手动关联优先级最高，并可恢复自动匹配。

已完成的检查：[0.1.2 构建与设备测试](https://github.com/longzhousz/AMI/actions/runs/39750502131)。

## 0.1.1 启动修复

0.1.0 优化 Preview 在启动 AndroidX Startup 时崩溃。已在 [Android 17 优化版复现任务](https://github.com/longzhousz/AMI/actions/runs/39728862319) 中取得日志：`NoSuchMethodException: androidx.work.impl.WorkDatabase_Impl.<init> []`。WorkManager 传递依赖的 Room 2.6.1 只保留了数据库类，R8 移除了反射创建数据库所需的无参构造方法。

0.1.1 显式保留 Room 数据库的无参构造方法，保留代码压缩、资源缩减和不可调试设置。版本号递增，包名与本地预览签名保持一致。旧版 0.1.0 不应再用于安装。

CI 新增独立的优化 APK 检查：安装实际 Preview，连续两次冷启动，验证曲库和导入入口，进入设置页，保存 APK SHA-256、UI XML、截图和崩溃日志。手动任务支持检查之前的构建产物，以及 Release 中的实际交付 APK。

修复版实际交付 APK 已通过 [独立安装启动检查](https://github.com/longzhousz/AMI/actions/runs/39730306251)：Android 11 / API 30 与 Android 17 / API 37.0 各两次冷启动，曲库、导入入口和设置页均渲染成功，无进程崩溃。测试从发行页下载 APK，SHA-256 与本地交付文件完全一致：`72dc0eb4d3a47eaa0164e92296d24ec9dbf932c07516e9f949306c055dd33f46`。本地与发行 APK 的签名证书均和先前发出的 0.1.0 一致，可覆盖安装。

这些是带硬件加速的模拟器验证；仍需要用户在 vivo X300 上确认实际启动和播放体验。

## 测试覆盖

核心测试覆盖 LRC BOM、offset、重复时间、无时间歌词；CUE 多文件、75 帧时间码和异常时间；专辑归组、手动排序；经典 NCM 解码、封面与元数据、截断、异常长度、取消和仅读取头部。NCM 测试使用不规则短读跨越缓冲区验证流式状态。

两套设备上均执行了以下六项测试：

1. SQLite 重新打开、重扫元数据后保留收藏、手动曲序和首次导入时间。
2. Android Keystore 加密写入、更换、删除，磁盘无密钥明文。
3. 缓存清理保留被引用的解码音频与源文件。
4. 原生 MediaSession 播放 CUE clip 的相对时长和 seek，顺序播放结束后重新播放。
5. 空曲库、收藏导航、设置和深色主题渲染；导入按钮文字保持完整高度。
6. 通过私有、仅 Debug 存在的 document URI 测试提供程序，验证音频、LRC、封面与 CUE 导入，以及重叠授权树去重和重扫收藏保留。

第六项测试验证真实 ContentResolver 与音频元数据链路，不替代系统文件选择器的真机权限验收。测试提供程序不会打包进 Preview 或 Release。CI 保存测试报告，并尝试导出界面截图。

本地复现：连接设备后运行 `cd android && ./gradlew connectedDebugAndroidTest`。
