# AMI 界面设计规范

AMI 的界面追求简洁、优雅。对标 iOS 的内容优先、液态玻璃层级和连续动效，同时遵循 Android 的系统返回、安全区、字体缩放和无障碍交互。[Apple 人机界面指南 · 材质](https://developer.apple.com/design/human-interface-guidelines/materials)

## 内容与层级

- 封面、曲名和歌词是页面主体。曲库和设置首页省去重复的大标题，菜单只留必要的选项名称，解释放到需要它的详情页。
- 浅色和深色主题沿用 AMI 的字号、字重和语义色。主操作、当前选中项和辅助信息有清楚的层级。用形状或勾选标出选中项，同时提供无障碍状态。
- 专辑封面用完整方形原图，迷你播放器缩略图沿用 9 dp 圆角。歌曲行保持轻量，悬浮控件才使用玻璃高光和阴影。
- 本地与网易云共用曲库网格、专辑详情和封面转场。封面下显示歌曲数和总时长，溢出的专辑名沿用歌曲名的点按展开。返回曲库时回到原专辑卡片和滚动位置。
- 曲库首屏内容从状态栏下方开始，滚动时封面可进入透明状态栏和悬浮控件后方。控件遵循系统安全区，系统栏图标随主题与沉浸状态调整。

## 液态玻璃

- 底栏、迷你播放器、悬浮工具栏、分段控件、菜单和对话框沿用 AMI 的玻璃组件。曲库搜索与发现入口悬浮在封面网格上方。优先复用 `GlassSurface`、`GlassDropdownMenu` 和 `GlassAlertDialog`，形状、取色和折射集中在 [材质组件](../app/src/main/java/com/longzhousz/ami/ui/LiquidGlass.kt)。
- 玻璃取自控件下方的真实页面与内容，用模糊、折射、浅深主题染色和克制的边缘高光建立层次。采样层与控件分开，滚动时背景随之变化。
- 菜单贴近触发控件。文字密集的浮层可用更强的模糊和更厚的半透明染色，压低底层字形与反差，让封面的色彩仍能透出。菜单以一层玻璃承载选项；容器保持透明，避免第二层实色覆盖材质。
- 弹窗与页面处于不同窗口时，按屏幕位置对齐独立的 GPU 背景层。队列弹层沿用自己持有的背景与玻璃源。效果随可见性停启，复用现有绘制与封面缓存，避免逐帧截图和像素回读。[材质实现](LIQUID_GLASS.md)

## 手势与动效

- 轻点完成主操作，长按承载当前控件的附加操作。只有在网易云曲库中长按当前的「网易云」才打开收藏专辑排序，勾选标出「默认」或「随机」。选择、点击外部和系统返回都可关闭菜单。
- 触控区域至少 48 dp。纯图标操作有明确的无障碍名称，长按有动作说明，菜单读出选中状态。窄屏和大字号时，标签及状态仍应完整可读。[Android 无障碍指南](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)
- 优先复用共享封面、`AmiMotion` 和已有返回手势。过渡衔接点按的对象，能够被后续手势打断。内容移出视口或被覆盖时，停止无意义的动画。[播放流程](PLAYBACK_FLOW.md)

## 界面变更验收

- 在模拟器沿真实入口走一遍，检查普通点击、长按、选择、点外关闭、系统返回和快速重开等相关操作。相同组件涉及本地与网易云时分别走通。
- 浅色、深色和大字号都看一次。在纯色和高反差封面或文字上方检查玻璃，确认底层色彩随内容变化、边缘有折射、控件文字和选中态清楚。
- 记录实际使用的设备、夹具和覆盖路径。真机流畅度与系统集成使用真机证据。[本地开发](LOCAL_DEVELOPMENT.md)
