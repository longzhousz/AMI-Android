# Android 0.1.8：曲库、连续操作与后台播放验证

应用内保持原有入口，不增加性能面板、翻译任务列表或历史界面。

## 歌词按需读取

schema 4 将歌曲的歌词正文迁至独立表；升级按最多 128 首分批转移，保留收藏、排序、初次导入时间、译文、手动歌词及播放队列。原来的歌词列留空，不在启动时执行整库 VACUUM。

曲库查询只读取曲目信息、歌词可用标记和版本；手动歌词及数字歌词的元数据使用覆盖索引，不将正文装入列表。当前歌曲按需读取，前台最多预取下一首；缓存按正文及解析结果的估算大小限制为 2 MiB，超大文档不进入缓存。正在显示的单份文档可以超过缓存预算；这不是整个进程内存的上限。图片缓存另设为应用可用堆空间的 12%。

退到后台后停止预取并清空预取缓存。后台恢复直接读取队列元数据，应用主界面和歌词读取不参与系统媒体键启动。

## 连续操作

歌词与译文关联歌曲 ID、歌词版本、模型选择和风格。切歌或修改来源后取消旧任务；即使旧响应稍后返回，也不能覆盖新歌曲的正文、译文或忙碌状态。HTTP 连接取消时在 IO 线程关闭，不在主线程等待。

进度预览使用独立请求标识；旧 seek 的确认不能清除新预览。换歌重建局部进度时钟，上一首的时间不传给下一首。退出中的歌词冻结位置，并禁止其跳转操作作用于新歌曲。多次收起请求只完成一次；封面载入新图时复用上一次成功的缓存图，过期图片回调不能更新当前占位。

## 标准系统媒体接入

普通浏览根仍为空；带 `EXTRA_RECENT` 的系统浏览请求返回 `ami-recent`，最多提供当前可恢复的一首曲目，等待队列恢复后再返回。换歌按事件通知订阅方，不做周期查询。

声明 Media3 的标准 `MediaButtonReceiver`，让系统可以在进程回收后通过媒体键启动服务。系统播放恢复使用保存队列，不打开主界面。此接入依据 [Media3 播放恢复](https://developer.android.com/media/media3/session/background-playback#resumption)及[媒体内容服务](https://developer.android.com/media/media3/session/serve-content)。

vivo 专属能力仍按 [OriginOS 兼容性记录](ORIGINOS_COMPATIBILITY.md)区分。标准媒体接入不保证原子随身听、原子岛或厂商音效名单已经收录。

## 自动验证与证据

设备回归保留原有全部断言，并增加：

- 长歌词超过默认 CursorWindow 容量时，列表不携带正文，按需读取仍完整；手动/数字歌词切换及版本更新使缓存正确失效。
- schema 1/2/3 升级、收藏/曲序/译文/队列保留。
- 一万首曲目列表不保留歌词字符；同一份一千首、每首约 8 KiB 歌词的夹具记录完整查询与轻量查询的内存快照。
- 旧翻译请求晚返回、后台连续切歌、进度拖动与多次收起。
- 系统最近曲目、熄屏播放、临时音频焦点失去/恢复、后台定时停止。
- 主机独立进行 SIGKILL 回收，然后只用系统媒体键恢复/暂停；检查前台播放服务和没有打开主界面。它与用户主动“强行停止”应用是不同的测试场景。

`qa/performance/` 保存内存、帧统计、连续操作记录及可用的 Perfetto 轨迹；测试结束后导出到设备测试产物中的 `performance.tar`。回收恢复的证据保存在 `device-screenshots/recovery/`。这些均为开发与测试产物，不增加应用界面。

Android 17 自动化使用不带 Google 后台组件的标准 AOSP 镜像，保留动画与全部界面断言。模拟器上的内存、时长和帧统计用于定位，不作为 vivo 真机帧率或续航提升比例。

## vivo 真机操作

当前工作区未连接 vivo 手机，不能把模拟器结果称作 vivo 真机验收。准备 Android platform-tools，在手机开启 USB 调试并允许电脑连接。安装预览包后，先在手机上选歌播放。

查看设备：

```sh
adb devices -l
```

在项目根目录运行一次快照：

```sh
python3 .github/scripts/ami-device-check.py --serial YOUR_SERIAL --scenario snapshot --output artifacts/vivo-snapshot
```

熄屏播放 30 分钟：先开始播放并熄屏，再运行：

```sh
python3 .github/scripts/ami-device-check.py --serial YOUR_SERIAL --scenario screen-off --duration 1800 --output artifacts/vivo-screen-off
```

蓝牙、来电、进程恢复分别用 `--scenario bluetooth`、`call`、`recovery` 保存证据。在采集期间由使用者连接/断开耳机、接听/结束实际来电或执行预定的进程回收操作；脚本不会替使用者拨号、修改应用设置、开启后台白名单或操作播放。

脚本记录手机型号、系统版本、音乐声明、媒体会话、音频路由、前台服务、内存及电量相关系统统计；不读取应用数据库、歌词正文或 API Key，蓝牙地址会遮盖。`verdict=evidence_only` 表示这些是诊断证据，不会自动把未执行的物理操作标为通过。USB 供电和调试本身会影响耗电观察，不据此直接换算真实续航。

逐项确认：

1. 锁屏与控制中心的歌名、封面、进度、播放/暂停及切歌。
2. 熄屏期间持续播放，暂停后没有持续歌词计算；短暂中断后按系统音频焦点恢复。
3. 蓝牙断开正确暂停；重连后的行为符合系统和用户操作，不自行抢占其他音频。
4. 实际来电接听后停止音乐输出，结束通话后正确恢复或保持暂停。
5. 系统回收后通过系统媒体键或恢复入口继续播放；用户主动强行停止后的行为遵守 Android 限制。
6. 原子随身听/原子岛能否选择 AMI，结合 OriginOS 完整版本单独记录，不能由上面普通媒体控制通过推定。
